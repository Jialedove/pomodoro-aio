# 真实 Obsidian 回归清单

仅在明确授权后执行 `npm run install:vault`，安装前确认目标插件目录中的 `data.json` 已存在且需要保留。

## 普通模式

- 启动 1 分钟专注，暂停/继续多次，确认暂停期间倒计时不变化。
- 手动完成约 5 分钟，确认任务行增加 `0.2🍅`，当日 frontmatter 与任务行总和一致。
- 自然完成测试一次短休、一次长休，确认自动衔接时 Ribbon 只关闭提醒，不重启正在运行的阶段。
- 关闭自动衔接，确认 Ribbon 点击才开始下一段；修改设置后仍使用待确认阶段保存的时长。

## 循环模式

- 配置 A/B 不同任务名和时长，确认 A → B → A 交替且不插入休息。
- 阶段完成后修改下一槽位设置，再点击 Ribbon，确认仍使用 journal/attention 中保存的任务名和时长。
- 若 Workspaces Plus 不可用，确认计时仍可启动、完成和写入日记。

## 快速记录

- 在普通和循环界面分别输入内容并按 Enter，确认默认以 `- [ ]` 写入当日日记的 `Inbox`。
- 点击“记想法”，确认以普通列表项写入；连续记录不会覆盖已有内容。
- 通过命令面板运行“快速记录”，确认 Enter 记为待办、Shift+Enter 可换行，并在写入时压成单行。
- 修改快速记录区域标题，确认写入指定区域；区域不存在时自动创建且不破坏 frontmatter、后续标题和原换行格式。
- 关闭“找不到当天文件时自动创建”并移走当日日记，确认写入失败时不会产生新文件。

## 恢复与边界

- 在专注写入日记后强制退出/重载，确认不会重复增加番茄。
- 在 frontmatter 或项目写入失败时重载，确认进入待恢复状态，修复后可继续且不重复记账。
- 外部修改目标任务行或项目 frontmatter，确认进入冲突并保留用户内容。
- 休眠/唤醒后确认剩余时间按绝对时间校正；到点瞬间点击暂停不能卡在零剩余暂停态。
- 窄侧栏打开视图，确认任务、按钮和循环两行仍可操作；关闭再打开视图不残留监听器。
- 修改设置并重载，确认设置正常恢复；确认插件目录中的 `data.json` 未被覆盖。

记录每项结果；任一失败先保留运行态和日志，再回到自动化测试定位，不直接清除 journal。
